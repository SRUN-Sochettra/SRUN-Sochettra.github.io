# Contributing

Keep changes focused on the existing Next.js App Router structure. Preserve the central portfolio records and distinguish the portfolio implementation from the systems it showcases.

Run the declared lint, typecheck and build scripts, then build the Pages target with the intended origin. Report actual results, not results copied from historical implementation notes. Inspect generated homepage semantics, canonicals, sitemap and direct case-study routes.

For interaction changes, test keyboard and touch, mobile-menu focus restoration, reduced motion, 200% zoom, narrow screens, failed assets, JavaScript disabled, restricted localStorage and Back/Forward restoration. Stage controls and decorative mock interfaces should not imply live provider or device integration.

Keep source links accurate after repository renames. Do not invent screenshots, resume paths, project metrics, production guarantees or licence grants. Do not run legacy cleanup scripts as part of an unrelated documentation change.

Pull requests should explain the problem, focused changes, checks actually run, remaining gaps and rollback. For sensitive reports, see [SECURITY.md](SECURITY.md).
